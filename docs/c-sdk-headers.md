# Apple OSS macOS C headers

This repository builds a standalone C header tree for macOS arm64
cross-compilation from locked Apple OSS sources and local compatibility
recipes. Each qualified Apple install command contributes its public headers.
The installed-header tests and SDK review probe measure the result. Clang resource
headers, libc++, the libunwind runtime, libraries, and frameworks come from
separate toolchain inputs.
The retained Apple OSS `libunwind` source supplies only
`mach-o/compact_unwind_encoding.h`, a Mach-O format header named by Zig's C
probe. The installer does not publish `unwind.h`, `libunwind.h`, or
`__libunwind_config.h`; those remain toolchain-owned.

## Generate the C installation

Run from the repository root on macOS. The installer uses Make, CMake, Ninja,
Python 3, Perl, system MIG, and standard command line tools such as `ed`,
`unifdef`, `awk`, `realpath`, and `shasum`. CMake and Ninja default to tools on
`PATH` and can be set with `CMAKE` and `NINJA`. Run from the repository root
on Apple Silicon:

```sh
make prepare-c-sources prepare-llvm SDK=macosx26.5
make install SDK=macosx26.5 OUT=/tmp/apple-oss-c-headers
```

Use `CLANG=/path/to/clang` to supply a compiler explicitly.

Pass the SDK lock name explicitly. To build the older C source set, run `make prepare-c-sources SDK=macosx26.0`
and `make install SDK=macosx26.0` with the already prepared Clang. See [the source locks](../locks/README.md) for preparation, offline operation,
and how to add a version. The output directory must be new.
The installer copies the selected lock as `source-lock.json` and stages each upstream install
separately, generates public MIG headers, and merges the result.
It emits one `header-manifest.tsv` with each header's origin, producer,
selection rule, inputs, transformation, and SHA-256.
See [the components](../components/README.md) for the production steps.

## Test the C installation

Run the suite against the tree generated by `make install`:

```sh
make test SDK="$SDK" CLANG="$LLVM_CLANG" OUT=/tmp/apple-oss-c-headers
```

See [the tests](../tests/c_header_installation/README.md) for the checks and host requirements.

See the [release build](../release/README.md) for the linkable SDK archive.

## C link coverage

In the macOS 26.5 arm64 reference, the shipped header set reaches
libSystem and the separate resolver, iconv/charset, zlib, BSM and IPsec
libraries. The C archive includes their stubs. The declarations of
`DebugStr` and `Debugger` in `MacTypes.h` need CarbonCore through
CoreServices. `OSReportWithBacktrace` in `libkern/OSDebug.h` is a DriverKit
interface.

The header comparison at deployment target 11.0 found 2,731 distinct
reference imports through libSystem. The composed stub supplies 2,724.
The seven differences are the previously deferred denormals environment
and modern logging interfaces.

- `__FE_DFL_DISABLE_DENORMS_ENV`
- `__os_log_create`, `__os_log_debug_impl`, `__os_log_disabled`,
  `__os_log_error_impl`, `__os_log_fault_impl`, `__os_log_impl`

The archive retains the pinned XNU userspace logging header and its
older linker names. The existing [provenance decisions](../.agents/skills/review-macos-c-sdk/scripts/sdk_review/headers/data/macosx26.5/tested-header-repairs.md)
describe the remaining work for the modern declarations. The
[linker audit](../.agents/skills/review-macos-c-sdk/scripts/sdk_review/linkage/sdk_header_linkage.md)
describes the reference comparison and its direct-include limits.
